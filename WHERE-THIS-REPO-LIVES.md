# WHERE THIS REPO LIVES

## The one true location

```
C:\Users\SCSpeakers\Documents\GitHub\Speakers\Speakers
```

Everything in this file exists because the project briefly had two working copies
and that cost real time. Read this before assuming where you are.

## What went wrong

The project was built at `C:\Users\SCSpeakers\Desktop\The TARDIS\SpeakersBureau`.
The client then created a repository at
`C:\Users\SCSpeakers\Documents\GitHub\Speakers\Speakers` and asked for the work to
live there. The two were connected - history merged, the client's `.gitattributes`
adopted - and the Documents repository became canonical.

**The Desktop copy was never removed.** It stayed on disk with its own `.git`, a
`local` remote pointing at the canonical repo, and a working tree that went on
diverging.

The cost was not the disk space. It was that two directories both looked like the
project, and which one you were standing in determined what you were reading:

- A build was reported green while the Desktop copy was 3 commits behind.
- A file comparison read the Desktop copy and reported the canonical repo as
  missing files it demonstrably had.
- The events work was written into the Desktop copy, so integrating it took a
  manual 27-file copy and a careful diff.
- The Desktop copy's `data/events.json` still held the wrong county on a
  Greenwood polling-place instruction, alongside the corrected version in the
  canonical repo.

## How to tell which one you are in

Ask, in order:

1. `git log --oneline -1` - the canonical repo is at or past
   `24515d8 Drop the masthead curator title, cut events header slop, fix a live
   comment leak`.
2. `Test-Path test\no-comment-leak.test.mjs` - the leak guard exists only in the
   canonical repo.
3. `git branch --list 'archive/*'` - the canonical repo has
   `archive/desktop-copy-2026-10-05`; the Desktop copy does not.

If any of those disagree with where you think you are, stop and move. An agent
session can be repointed with `opencode.session_move`.

## The Desktop copy

```
C:\Users\SCSpeakers\Desktop\The TARDIS\SpeakersBureau
```

Before anything in it was touched, all 72 of its tracked files were checked against
the canonical repository's git history. **56 were byte-identical to a blob already
in history. 16 were not** - they were genuinely divergent content, including a
stale `build-log.md`, a stale `ROADMAP.md`, an outdated `data/events.json` with the
wrong county, and older versions of the calendar and its tests.

Those 16 were **committed to the `archive/desktop-copy-2026-10-05` branch** before
any cleanup. After archiving, the same check reported 72 of 72 files present in
history and **0 unique**.

So the Desktop copy's content is recoverable from git, and the folder itself is
safe to delete whenever you decide to. That decision was left to the client, not
taken unilaterally.

To see the archived state:

```powershell
git log --oneline archive/desktop-copy-2026-10-05
git diff main archive/desktop-copy-2026-10-05 --stat
```

`main` was never modified by the archiving. It is the working branch.

## What is authoritative, and what is not

| Thing | Authoritative |
| --- | --- |
| Working directory | `Documents\GitHub\Speakers\Speakers` |
| Branch to build and deploy | `main` |
| Article dataset | `data/articles.json`, written by `npm run fetch` |
| Event dataset | `data/events.json`, hand-maintained, validated by `npm run events:check` |
| Publication list | `data/sources.yml`, the only file a human edits to add a source |
| Colour values | `src/styles/themes.css`, and nowhere else |
| Deployable output | `dist/`, disposable, regenerated by `npm run build` |
| Design decisions and their reasons | `ROADMAP.md` |
| What was tried and what broke | `build-log.md`, newest entry first |
| Machine facts and traps | `environment-log.md` |

## The rule this file exists to enforce

**One working copy. If a second one appears, the new one is either adopted
immediately or archived before the old one is touched.** Not "later". Not after
someone has spent an hour diffing line endings.
